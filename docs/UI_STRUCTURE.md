## 0. คำสั่งสำหรับผู้ออกแบบ (คัดลอกส่วนนี้ไปเป็น Prompt ได้)

คุณคือ Product/UI Designer ออกแบบแอปมือถือ **RiderOS AI** สำหรับไรเดอร์ส่งอาหาร (มอเตอร์ไซค์) ในประเทศไทย
ให้ออกแบบ UI ใหม่ทั้งแอปจากโครงสร้างในเอกสารนี้ โดย:

1. **ห้ามตัดหรือเปลี่ยนความหมาย** ของข้อมูล ช่องกรอก กฎ Validation สถานะหน้าจอ และข้อความบังคับใน §2 — ข้อมูลทุกอย่างมาจาก API ที่มีอยู่แล้ว
2. **ห้ามเพิ่ม Feature ที่ไม่มีใน API** (เช่น เชื่อมต่อ Grab/LINE MAN, แชท, แผนที่นำทาง, ทำนายรายได้จาก AI) ถ้าอยากเสนอ ให้แยกเป็นหัวข้อ "ข้อเสนอเพิ่มเติม"
3. ปรับได้อิสระ: สี ฟอนต์ ระยะห่าง รูปทรง ไอคอน ลำดับ/การจัดกลุ่มบนหน้า รูปแบบ Navigation วิธีแสดงกราฟ การใช้ Bottom sheet/Dialog แทนหน้าเต็ม
4. ต้องใช้ได้จริงบนจอ 360–430 dp, มือเดียว, กลางแดด (Contrast สูง), ขณะสวมถุงมือ (ปุ่มแตะ ≥ 48 dp)
5. ทำทั้ง Light และ Dark

**สิ่งที่ต้องส่งกลับ (เพื่อให้นักพัฒนา Implement ได้ตรง):**
- **A. Design tokens** เป็นตาราง: สี (ชื่อ Role + Hex ทั้ง Light/Dark), Typography (ชื่อ style, ฟอนต์, ขนาด, น้ำหนัก, line-height), Spacing scale, Radius, Elevation/Shadow, Icon set
- **B. Components**: แต่ละตัวบอกสถานะ (ปกติ/กด/ปิดใช้งาน/Loading/Error) และขนาด — อย่างน้อย: ปุ่ม Primary/Secondary/Text, ช่องกรอก (ข้อความ/ตัวเลข/วันที่/เวลา/Dropdown/หลายบรรทัด), การ์ดสรุปตัวเลข, ไทล์ตัวเลข, Banner (info/warning/error/success), ป้าย DEMO, ป้าย "ค่าประมาณ", Empty/Error/Loading view, รายการ (List tile), Tab, Segmented control, Bottom navigation, Dialog ยืนยัน, SnackBar, กราฟแท่ง, แถบช่วง (Interval bar)
- **C. ทุกหน้าจอใน §5**: ลำดับองค์ประกอบจากบนลงล่าง + ตำแหน่งปุ่ม + ทั้ง 4 สถานะ (Loading/Empty/Error/Data) — เป็นข้อความหรือ Wireframe ก็ได้ ระบุชื่อหน้าให้ตรงกับรหัสในเอกสารนี้ (เช่น `S-HOME`)
- **D. Navigation map** ที่เสนอ (ถ้าเปลี่ยนจาก §4 ให้บอกเหตุผล)
- **E. ข้อความภาษาไทย** ที่อยากเปลี่ยน (ถ้ามี) เป็นตาราง เดิม → ใหม่

## 1. บริบทผลิตภัณฑ์

- **ผู้ใช้:** ไรเดอร์ส่งอาหารอิสระ ใช้มือถือ Android ระหว่างวัน ต้องการรู้ว่า "ทำงานวันนี้ได้กำไรจริงเท่าไหร่ ชั่วโมงละเท่าไหร่" และ "ร้านนี้ปกติใช้เวลาจากสั่งถึงรับอาหารนานแค่ไหน"
- **4 โมดูล:**
  1. **TrueProfit** — บันทึกรายได้/ค่าใช้จ่าย/ช่วงทำงาน → กำไรสุทธิจริง, ต่อชั่วโมง, แนวโน้ม ✅
  2. **Pickup Intelligence** — ทำนายเวลา **Order-to-Pickup** ของร้าน (ML) + สถิติร้าน + บันทึกเวลารอจริงของตัวเอง 🔜
  3. **Shift Simulator** — จำลองกะงานหลายแบบแล้วเปรียบเทียบกำไร **ที่ประมาณการ** 🔜
  4. **RoadContext** — รายงานเหตุบนถนน + แผนที่ ⏳
- **ไม่ใช่** แอปรับงาน ไม่เชื่อมแพลตฟอร์มใด ไม่ทำนายรายได้อนาคต ไม่นำทาง

## 2. กฎบังคับ (ห้ามละเมิดในงานออกแบบ)

1. **ทุกหน้าที่ดึงข้อมูลต้องมี 4 สถานะ:** Loading, Empty (พร้อมปุ่มพาไปสร้างข้อมูลแรก), Error (ข้อความไทย + ปุ่ม "ลองใหม่"), Data
2. **ห้ามมีปุ่มที่กดแล้วไม่ทำงาน** — Feature ที่ยังไม่พร้อมต้อง **ซ่อน** ไม่ใช่ทำเป็นสีเทา
3. **ตัวเลขเงินทุกตัวมาจาก Server** แสดงทศนิยม 2 ตำแหน่ง มีคั่นหลักพัน (`฿1,049.50`) · กำไรบวกสีเขียว ติดลบสีแดง ศูนย์สีปกติ · ค่าต่อชั่วโมงเมื่อไม่มีชั่วโมงทำงานแสดง "—" พร้อมคำอธิบาย
4. **แยก "ตัวเลขจริง" กับ "ค่าประมาณ" ให้ชัด** — ผลจาก Shift Simulator ต้องมีป้าย "ค่าประมาณ" ทุกที่ และห้ามปนกับ TrueProfit
5. **Pickup:** เรียกว่า **"Order-to-Pickup"** เสมอ (เวลาจากสั่งถึงรับอาหารที่ร้าน) — ห้ามเรียก "เวลารอของไรเดอร์" หรือ "เวลาทำอาหาร" · แสดงเป็น **ช่วง** (เช่น 6–21 นาที) ไม่แสดงตัวเลขเดี่ยวเป็นหลัก · ต้องมีคำเตือน "ค่าประมาณจากข้อมูลต่างประเทศ" + Disclaimer ทุกผล
6. หน้าข้อมูลโมเดลต้องมีข้อความ: *This research was supported by data provided by Meituan.*
7. ข้อมูลที่เป็น Demo ต้องมีป้าย **DEMO**
8. ข้อผิดพลาดของ Form แสดงใต้ช่องนั้น (Inline) · ข้อผิดพลาดจาก Server แสดงเป็น Banner เหนือปุ่มบันทึก · ปุ่มบันทึกระหว่างส่งแสดง Spinner และกดซ้ำไม่ได้
9. การลบต้องมี Dialog ยืนยันเสมอ (ลบแล้วกู้คืนไม่ได้)
10. ภาษาไทยทั้งหมด (ชื่อเฉพาะ เช่น TrueProfit, Order-to-Pickup, DEMO ใช้ภาษาอังกฤษได้) · วันที่แบบไทย `10 พ.ย. 2026` · เวลา 24 ชม. `18:30` · สัปดาห์เริ่มวันจันทร์

## 4. Navigation

**ปัจจุบัน:** ก่อน Login = หน้าเดี่ยวต่อกัน · หลัง Login = Bottom navigation 2 แท็บ (หน้าหลัก, กำไร) · ฟอร์มเปิดเต็มจอทับ Bottom navigation

**แผน (หลัง P3c):** Bottom navigation 5 แท็บ → หน้าหลัก · Pickup · กำไร · กะงาน · โปรไฟล์ (Phase 5 อาจเพิ่ม "ถนน" หรือย้ายเข้าเมนูอื่น — ผู้ออกแบบเสนอได้)

```
Splash ─┬─ (ไม่มี Session) → Login ─┬─ Register → (สำเร็จ) Login อัตโนมัติ
        │                          └─ Forgot → Forgot sent → Reset → Login
        ├─ (Login ครั้งแรก, ยังไม่ตั้งค่า) → Onboarding → หน้าหลัก
        └─ (มี Session) → หน้าหลัก

[แท็บ หน้าหลัก]  S-HOME → ฟอร์มรายได้ / ค่าใช้จ่าย / ช่วงทำงาน
[แท็บ Pickup]    S-PICKUP-SEARCH → S-RESTAURANT → S-PREDICTION-RESULT
                                              → S-PICKUP-LOG-FORM
                 S-PREDICTION-HISTORY · S-PICKUP-LOGS · S-MODEL-INFO · S-OWN-RESTAURANT-FORM
[แท็บ กำไร]      S-PROFIT → S-RECORDS (3 แท็บ) → ฟอร์มแก้ไข
[แท็บ กะงาน]     S-SHIFTS → S-SHIFT-FORM / S-SHIFT-DETAIL → S-SHIFT-COMPARE
[แท็บ โปรไฟล์]   S-PROFILE → S-RIDER-PROFILE-FORM · S-ACCOUNT-DELETE · S-MODEL-INFO
```

Session หมดอายุที่หน้าใดก็ตาม → กลับหน้า Login พร้อมข้อความ "เซสชันหมดอายุ"

## 5. หน้าจอทั้งหมด

รูปแบบ: **จุดประสงค์ · เนื้อหา (ตามลำดับปัจจุบัน) · การกระทำ · สถานะ · กฎ**

### 5.1 ก่อนเข้าสู่ระบบ ✅

**S-SPLASH** — เปิดแอปแล้วกู้ Session
- โลโก้ + ชื่อ "RiderOS AI" + Loading
- Error (เช่นออฟไลน์): หัวข้อ "เชื่อมต่อไม่สำเร็จ" + สาเหตุ + ปุ่ม "ลองใหม่" (ไม่ลบการ Login เดิม)

**S-LOGIN**
- โลโก้, ชื่อแอป, Tagline "ผู้ช่วยวางแผนงานและกำไรสำหรับไรเดอร์"
- Banner (ถ้ามี): "สมัครสำเร็จ กรุณาเข้าสู่ระบบ" / "ตั้งรหัสผ่านใหม่แล้ว" / "เซสชันหมดอายุ"
- ช่อง: อีเมล, รหัสผ่าน (ปุ่มแสดง/ซ่อน)
- ลิงก์ "ลืมรหัสผ่าน?" · ปุ่มหลัก "เข้าสู่ระบบ" · "ยังไม่มีบัญชี? สมัครสมาชิก"
- Error จาก Server: อีเมลหรือรหัสผ่านไม่ถูกต้อง, ลองบ่อยเกินไป (รอ N วินาที), เชื่อมต่อไม่ได้

**S-REGISTER**
- ช่อง: ชื่อที่แสดง (≤ 80), อีเมล (≤ 254), รหัสผ่าน (8–128 ตัว, ห้ามเหมือนชื่อหน้า @ ของอีเมล; Helper "อย่างน้อย 8 ตัวอักษร และไม่ใช่รหัสผ่านที่พบบ่อย"), ยืนยันรหัสผ่าน
- ปุ่ม "สร้างบัญชี" · ลิงก์กลับ Login
- Error จาก Server: อีเมลถูกใช้แล้ว, รหัสผ่านไม่ปลอดภัย

**S-FORGOT** → **S-FORGOT-SENT**
- ช่องอีเมล → ปุ่มส่ง → หน้ายืนยัน "ถ้ามีบัญชีนี้ เราได้ส่งลิงก์ไปแล้ว" + ปุ่ม "มีลิงก์/รหัสแล้ว" + กลับ Login
- (เฉพาะ Build ทดสอบ) หมายเหตุ DEV ONLY ว่าลิงก์อยู่ใน Log ของ Server

**S-RESET**
- ช่อง: ลิงก์รีเซ็ตทั้งเส้นหรือรหัส, รหัสผ่านใหม่, ยืนยัน → ปุ่ม "ตั้งรหัสผ่านใหม่" → Login พร้อม Banner

**S-ONBOARDING** (Login ครั้งแรกเท่านั้น)
- คำอธิบาย: ใช้ข้อมูลนี้คำนวณต้นทุนต่อกิโลเมตร
- ช่อง (ไม่บังคับทุกช่อง): ประเภทยานพาหนะ (Dropdown: ไม่ระบุ, มอเตอร์ไซค์, มอเตอร์ไซค์ไฟฟ้า, จักรยาน, รถยนต์, อื่นๆ), อัตราสิ้นเปลือง กม./ลิตร (> 0, ≤ 9999.99), ราคาน้ำมัน บาท/ลิตร (≤ 999999.99), ค่าเสื่อม บาท/กม. (ทศนิยม 4 ตำแหน่ง)
- ข้อความ: เขตเวลา Asia/Bangkok, สกุลเงิน THB
- ปุ่ม "บันทึกและเริ่มใช้งาน" · ปุ่มรอง "ข้ามไปก่อน" (บันทึกค่าว่าง ไม่ถามซ้ำ)

### 5.2 หน้าหลัก ✅

**S-HOME** (แท็บ หน้าหลัก)
- Header: "สวัสดี {ชื่อ}" + "เข้าสู่ระบบด้วย {อีเมล}" · ปุ่ม Logout ที่ AppBar (ชั่วคราว จะย้ายไปโปรไฟล์)
- การ์ด **วันนี้ · {วันที่}**: กำไรสุทธิ (ใหญ่), รายได้, ค่าใช้จ่าย, ชั่วโมงทำงาน, กำไรสุทธิ/ชม.
- การ์ด **สัปดาห์นี้ · {จันทร์–อาทิตย์}**: ข้อมูลชุดเดียวกัน
- ถ้าไม่มีชั่วโมงทำงาน: "—" + "ยังไม่มีชั่วโมงทำงาน จึงยังคำนวณค่าต่อชั่วโมงไม่ได้ (บันทึกช่วงทำงาน หรือกรอกชั่วโมงในรายได้)"
- การ์ด **บันทึกด่วน**: เพิ่มรายได้, เพิ่มค่าใช้จ่าย, บันทึกช่วงทำงาน, ลิงก์ "ดูกำไรทั้งหมด (TrueProfit)"
- Empty: วันนี้และสัปดาห์นี้ไม่มีรายการ → "ยังไม่มีรายการในวันนี้และสัปดาห์นี้" + คำแนะนำ (การ์ดบันทึกด่วนยังแสดง)
- ดึงลงเพื่อรีเฟรช
- 🔜 อาจเพิ่ม: ทางลัด Pickup (ค้นร้าน), กะงานที่วางแผนไว้ — ผู้ออกแบบเสนอได้ ถ้าใช้ข้อมูลจาก §6

### 5.3 TrueProfit ✅

**S-PROFIT** (แท็บ กำไร)
- AppBar: "TrueProfit" + ปุ่มไปหน้ารายการทั้งหมด
- Segmented: วัน / สัปดาห์ / เดือน
- แถบช่วงเวลา: ‹ ก่อนหน้า · ป้ายช่วง (`10 พ.ย. 2026` / `9 พ.ย. – 15 พ.ย. 2026` / `พฤศจิกายน 2026`) + "ช่วงปัจจุบัน" · ถัดไป › (ซ่อนเมื่ออยู่ช่วงปัจจุบัน)
- การ์ด **สรุปกำไรจริง**: กำไรสุทธิ, รายได้, ค่าใช้จ่าย, ชั่วโมงทำงาน, กำไรสุทธิ/ชม., รายได้/ชม., จำนวนรายการ (รายได้/จ่าย/กะ)
- การ์ด **แนวโน้มกำไรสุทธิ**: กราฟแท่ง (วัน = 30 แท่ง, สัปดาห์ = 12, เดือน = 12) บวกเขียว/ลบแดง, แตะแท่งดูวันที่+จำนวนเงิน, ป้ายแกน X ต้น/กลาง/ท้าย
- หมายเหตุ: "ตัวเลขทั้งหมดคำนวณโดยเซิร์ฟเวอร์จากรายการที่คุณบันทึกจริงเท่านั้น (ไม่รวมค่าประมาณจาก Shift Simulator) · สัปดาห์เริ่มวันจันทร์ · เขตเวลา {zone}"
- Empty: ช่วงนี้ไม่มีรายการ / กราฟไม่มีข้อมูล (ข้อความแยกกัน)

**S-RECORDS** (รายการทั้งหมด) — Tabs: **รายได้ · ค่าใช้จ่าย · ช่วงทำงาน**
- รายการเรียงใหม่→เก่า, เลื่อนใกล้ท้ายโหลดเพิ่ม + ปุ่ม "โหลดเพิ่ม" + ท้ายสุด "แสดงครบทุกรายการแล้ว" · ดึงลงเพื่อรีเฟรช
- รายได้: จำนวนเงิน · วันที่ · แหล่งรายได้ · N ออเดอร์ · [DEMO]
- ค่าใช้จ่าย: ไอคอนหมวด · จำนวนเงิน · หมวด · วันที่ · รายละเอียด · [DEMO]
- ช่วงทำงาน: วันที่ + `18:00 – 22:30` (หรือ `01:30 (วันถัดไป)`) · ระยะเวลา · ออเดอร์ · กม. · [DEMO]
- ปุ่มลอย: เพิ่มรายได้ / เพิ่มค่าใช้จ่าย / บันทึกช่วงทำงาน (เปลี่ยนตามแท็บ)
- Empty แต่ละแท็บ: หัวข้อ + คำอธิบาย + ปุ่มเพิ่ม · Error โหลดหน้าถัดไป: ข้อความ + "ลองใหม่" ท้ายรายการ (รายการเดิมยังอยู่)
- แตะรายการ → ฟอร์มแก้ไข

**S-INCOME-FORM** (เพิ่ม/แก้ไขรายได้) — AppBar มีปุ่มลบเมื่อแก้ไข
| ช่อง | กฎ |
|---|---|
| วันที่ | บังคับ, ปฏิทิน, 1 ม.ค. 2000 – วันนี้ |
| จำนวนเงิน | บังคับ, ≥ 0, ทศนิยม ≤ 2, ≤ 9,999,999,999.99 |
| แหล่งรายได้ | ไม่บังคับ, ≤ 50 ตัว, Helper "พิมพ์เอง เช่น ชื่อแพลตฟอร์ม (แอปไม่ได้เชื่อมต่อแพลตฟอร์มใด)" |
| ผูกกับช่วงทำงาน | ไม่บังคับ, Dropdown ช่วงทำงานที่เริ่มในวันที่เลือก (มี Loading/Error+ลองใหม่ของตัวเอง) |
| ชั่วโมงทำงาน | ไม่บังคับ, > 0 และ ≤ 24, **ซ่อนเมื่อผูกช่วงทำงาน** |
| จำนวนออเดอร์ | ไม่บังคับ, จำนวนเต็ม 0–10,000 |
| ระยะทาง (กม.) | ไม่บังคับ, ≥ 0, ทศนิยม ≤ 2 |
| หมายเหตุ | ไม่บังคับ, ≤ 500, หลายบรรทัด |
- ปุ่ม "บันทึก" → กลับหน้าก่อน + SnackBar "บันทึกแล้ว" · Error Server เป็น Banner
- โหมดแก้ไข: Loading ระหว่างโหลด, Error "ไม่พบรายการนี้ (อาจถูกลบไปแล้ว)" + ลองใหม่

**S-EXPENSE-FORM** — วันที่ (บังคับ), หมวดหมู่ (บังคับ: น้ำมัน/ชาร์จไฟ, ซ่อมบำรุง, ค่าเสื่อมราคา, อื่นๆ), จำนวนเงิน (บังคับ, กฎเดียวกับรายได้), รายละเอียด (≤ 500) · ลบได้เมื่อแก้ไข

**S-SESSION-FORM** (ช่วงทำงาน) — วันที่เริ่ม, เวลาเริ่ม, เวลาเลิก (Time picker 24 ชม.), Helper ใต้เวลาเลิก "รวม 4 ชม. 30 นาที · เลิกวันถัดไป", จำนวนออเดอร์, ระยะทาง, หมายเหตุ
- ค่าเริ่มต้นเมื่อสร้างใหม่: 4 ชั่วโมงล่าสุดถึงตอนนี้
- เวลาเลิก ≤ เวลาเริ่ม = เลิกวันถัดไป · เวลาเท่ากัน = Error "เวลาเริ่มและเวลาเลิกต้องไม่ตรงกัน"
- Error Server: "ช่วงเวลานี้ซ้อนกับช่วงทำงานที่บันทึกไว้แล้ว", "ช่วงทำงานยาวได้ไม่เกิน 24 ชั่วโมง"

### 5.4 Pickup Intelligence 🔜 (P3c)

**S-PICKUP-SEARCH** (แท็บ Pickup)
- ช่องค้นหาชื่อร้าน · ตัวกรองแหล่ง: ทั้งหมด / ร้านจากข้อมูลชุดฝึก (Dataset) / ร้านของฉัน
- รายการร้าน: ชื่อ · ป้ายแหล่ง (Dataset / ของฉัน) · ระดับข้อมูล (เพียงพอ ≥ 30 ออเดอร์ / จำกัด 5–29 / ไม่เพียงพอ ≤ 4) · จำนวนออเดอร์ในข้อมูล
- ปุ่ม "เพิ่มร้านของฉัน" · ทางเข้า: ประวัติการทำนาย, บันทึกเวลารับของฉัน, ข้อมูลโมเดล
- Empty (ค้นไม่เจอ): ข้อความ + ปุ่มเพิ่มร้านของฉัน
- หมายเหตุ: ร้าน Dataset มาจากข้อมูล Meituan (จีน) ไม่ใช่ร้านในไทย

**S-RESTAURANT** (รายละเอียดร้าน)
- Header: ชื่อร้าน, แหล่ง, ระดับข้อมูล
- ปุ่ม **"ทำนาย Order-to-Pickup ตอนนี้"** — **แสดงเฉพาะร้าน Dataset** (ร้านของฉันทำนายไม่ได้ → ซ่อนปุ่ม)
- การ์ด **สถิติจากข้อมูลชุดฝึก** (เฉพาะร้าน Dataset): ภาพรวม (มัธยฐาน, ช่วง P25–P75 นาที, จำนวนออเดอร์) + ตาราง/Heatmap 24 ชั่วโมง แยก วันธรรมดา/เสาร์-อาทิตย์ (แต่ละชั่วโมง: จำนวนออเดอร์, มัธยฐาน; ชั่วโมงไม่มีข้อมูลแสดงว่าง)
- การ์ด **เวลารอจริงของฉัน** (จาก Pickup Log ของตัวเอง): มัธยฐาน, P80, จำนวนครั้ง, ความมั่นใจ (ไม่พอ < 5 ครั้ง = ไม่แสดงตัวเลข / ต่ำ 5–19 / ใช้ได้ ≥ 20)
- ปุ่ม "บันทึกเวลารับที่ร้านนี้"

**S-PREDICTION-RESULT**
- หัวข้อ "Order-to-Pickup โดยประมาณ" · **ช่วง `low–high` นาที (ใหญ่)** · ค่ากลางตัวเล็กเป็นข้อมูลรอง · "ช่วงนี้ครอบคลุมราว 80% ของออเดอร์ในข้อมูลทดสอบ"
- คำเตือน (Banner warning): "ค่าประมาณจากข้อมูลต่างประเทศ" (เสมอ) + "ข้อมูลร้านนี้มีจำกัด/ไม่เพียงพอ" (ถ้ามี)
- Disclaimer (ข้อความจาก Server) · เวอร์ชันโมเดล · เวลาที่ขอ
- Error: โมเดลไม่พร้อมใช้งาน (503), ร้านนี้ทำนายไม่ได้

**S-PREDICTION-HISTORY** — รายการ: ชื่อร้าน · ช่วงนาที · วันเวลา (ใหม่→เก่า, โหลดเพิ่ม)

**S-PICKUP-LOGS** + **S-PICKUP-LOG-FORM** — บันทึกเวลารอจริง
- ฟอร์ม: ร้าน (เลือก), เวลาถึงร้าน, เวลารับอาหาร (ต้องหลังเวลาถึง, รอ ≤ 3 ชม.), หมายเหตุ
- รายการ: ร้าน · รอ N นาที · วันเวลา · ลบได้ (ยืนยัน)

**S-OWN-RESTAURANT-FORM** — ชื่อร้าน (บังคับ), ตำแหน่ง (ไม่บังคับ; lat/lng — เห็นเฉพาะเจ้าของ)

**S-MODEL-INFO** — การ์ดโมเดล: สิ่งที่ทำนาย (Order-to-Pickup), ผลทดสอบเทียบ Baseline (MAE 4.51 vs 4.64 นาที), Coverage ของช่วง 80% (จริง 81.6%), ข้อจำกัด, แหล่งข้อมูล + License (CC BY-NC 4.0), **ข้อความ Acknowledgement บังคับ**

### 5.5 Shift Simulator 🔜 (P3c)

ทุกตัวเลขในโมดูลนี้ = **ค่าประมาณ** (ต้องมีป้าย) ไม่นับรวมใน TrueProfit

**S-SHIFTS** (แท็บ กะงาน)
- รายการ Scenario: ชื่อ · เวลา `17:00–22:00` · วัน (ถ้ากำหนด) · วิธีประมาณ · กำไรสุทธิประมาณ · ต่อชั่วโมง · ป้าย "ค่าประมาณ"
- เลือกได้ 2–5 รายการ → ปุ่ม "เปรียบเทียบ" (แสดงเมื่อเลือก ≥ 2 เท่านั้น)
- ปุ่มเพิ่ม Scenario · Empty: อธิบายว่า Scenario คืออะไร + ปุ่มสร้าง

**S-SHIFT-FORM** (สร้าง/แก้ไข)
- ชื่อ (บังคับ), เวลาเริ่ม, เวลาเลิก (ก่อนเวลาเริ่ม = ข้ามคืน; ยาว 30 นาที – 16 ชม.), วันในสัปดาห์ (ไม่บังคับ; จันทร์–อาทิตย์)
- วิธีประมาณ: **จากสมมติฐาน** (ค่าเริ่มต้น) / **จากประวัติของฉัน** (ต้องมีช่วงทำงาน ≥ 5 วันใน 84 วัน) — ห้ามแสดงตัวเลือก ML
- สมมติฐาน (แสดงเมื่อเลือก "จากสมมติฐาน"): ออเดอร์/ชม. (บังคับ), รายได้/ออเดอร์ (บังคับ), กม./ออเดอร์, กม./ลิตร, ราคาน้ำมัน/ลิตร, ค่าเสื่อม/กม. (สามช่องหลังเว้นว่าง = ใช้ค่าจากโปรไฟล์), ค่าใช้จ่ายคงที่ของกะ (ที่จอดรถ ข้าว ฯลฯ)
- Error Server: ความยาวกะไม่ถูกต้อง, ขาดสมมติฐาน, ประวัติไม่พอ

**S-SHIFT-DETAIL**
- ป้าย "ค่าประมาณ" · รายได้ประมาณ, ค่าใช้จ่ายประมาณ, กำไรสุทธิประมาณ, ต่อชั่วโมง · ช่วง ต่ำ–สูง (เฉพาะวิธีประวัติ: P20–P80 ของรายวัน) · ที่มา (ใช้วันเดียวกัน/ทุกวัน, จำนวนวัน) · คำเตือน (เช่น "ไม่รวมต้นทุนระยะทาง")
- ปุ่ม: คำนวณใหม่ด้วยข้อมูลล่าสุด, แก้ไข, ลบ (ยืนยัน), ผูกกับช่วงทำงานจริง (ไม่บังคับ)

**S-SHIFT-COMPARE**
- ตาราง/การ์ดเทียบ 2–5 Scenario: เวลา, รายได้, ค่าใช้จ่าย, กำไรสุทธิ, ต่อชั่วโมง (ทั้งหมดเป็นค่าประมาณ)
- ไฮไลต์ "กำไรสุทธิสูงสุด" และ "กำไรต่อชั่วโมงสูงสุด" (อาจเป็นคนละ Scenario)

### 5.6 โปรไฟล์ / ตั้งค่า 🔜 (P3c)
