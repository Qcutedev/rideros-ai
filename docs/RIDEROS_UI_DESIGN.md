> **อัปเดต 2026-11-18:** เอา Pickup Intelligence ออกจากแอปแล้ว (`docs/HANDOFF.md` §4.20). แท็บที่ 2 เป็น **ถนน** และการ์ด RoadContext ย้ายไปอยู่ในแถว "เครื่องมือ AI" ของ Home แทนการ์ด Pickup ส่วนที่พูดถึง Pickup ด้านล่างคือแบบเดิม

**เวอร์ชัน:** 2.0 (Lime Obsidian)\

## 1. เป้าหมายการออกแบบ

ออกแบบ RiderOS AI ให้เป็นแอปผู้ช่วยสำหรับไรเดอร์ส่งอาหารในประเทศไทย โดยมีภาพลักษณ์
**Urban Rider × Smart Mobility × AI Intelligence** สื่อถึงความคล่องตัว
ความน่าเชื่อถือ และการใช้ข้อมูลช่วยตัดสินใจ

แอปต้องดูเป็นผลิตภัณฑ์ที่ใช้งานจริง ไม่ใช่แค่ Dashboard สวย ๆ
หรือแอปบัญชีรายรับรายจ่ายทั่วไป

### Brand statement

**RiderOS AI --- Smart Rider, Smarter Journey**

แนวคิดหลัก (ปรับ 2026-11-16 จาก "Rider Green" เป็น "Lime Obsidian"): -
Modern Minimalist Luxury + Futuristic Lifestyle Technology ไม่ใช่หน้าตาแอปธนาคารสีเขียว -
พื้นหลังสีงาช้าง (Soft Ivory) สลับการ์ดหลายโทน ไม่ใช่การ์ดขาวทุกใบ -
Electric Lime ใช้กับปุ่มหลัก สถานะที่เลือก ความคืบหน้า และจุดเน้นสำคัญ -
การ์ด Obsidian สำหรับตัวเลขเด่น (Hero) และส่วนที่ต้องการ Contrast สูง -
ใช้กราฟและตัวเลขเพื่อสื่อสารข้อมูล ไม่ตกแต่งจนรบกวนการอ่าน -
AI ต้องอธิบายที่มาและข้อจำกัด ไม่แสดงผลเกินกว่าข้อมูลที่ระบบรองรับ

## 2. Visual direction

### 2.1 แนวทางหลัก: Lime Obsidian

ภาพรวมเหมือนระบบปฏิบัติการมือถือระดับพรีเมียม: - การ์ดมุมโค้งใหญ่ (24--28 dp)
สลับโทน Sage / Teal / Mist / Obsidian / Lime บนพื้น Ivory - ตัวเลขการเงินใหญ่ ชัด
(Display 44 บน Hero card) - ไอคอน Rounded ชุดเดียว วางในวงกลม/สี่เหลี่ยมมนสี Lime
(`IconWell`) - Gradient ใช้แค่แสง Lime จาง ๆ มุมบนขวาของการ์ด Obsidian -
แถบเมนูล่างเป็นแคปซูล Obsidian ลอย มีเม็ด Lime เลื่อนไปที่แท็บที่เลือก -
Dark mode ออกแบบแยก: พื้นเกือบดำ การ์ด Obsidian ยกระดับ ปุ่มหลักสี Lime
ไม่ใช่การกลับสีของธีมสว่าง - หลีกเลี่ยง Glassmorphism, Neon และองค์ประกอบ Sci-Fi

### 2.3.1 Surface tones

การ์ดเลือกโทนได้ 6 แบบ (`AppTone`: paper, mist, sage, teal, lime, obsidian) ผ่าน
`ToneCard` / `SectionCard(tone:)` / `TileGroup(tone:)` ทุกโทนมีธีมของตัวเอง
(`AppTheme.toned`) ข้อความ ปุ่ม และสีเงินข้างในเปลี่ยนตามพื้นอัตโนมัติ
เนื้อหาที่อ่านสีจาก `Theme.of(context)` ต้องสร้างใน `Builder` ใต้การ์ด
ไม่ใช่ใช้ `theme` ที่อ่านไว้ก่อนสร้างการ์ด
Test `surfaces_and_motion_test.dart` ตรวจ Contrast ≥ 4.5:1 ทุกโทนทั้งสองธีม
(ข้อความหลัก/รอง, Error, กำไรบวก, ข้อความบน Tile, ปุ่มหลัก, เนื้อหาบน Lime)

### 2.3.2 Motion

ทุกแอนิเมชันปิดเมื่อระบบเปิด "ลดการเคลื่อนไหว" (`MediaQuery.disableAnimations`):
การ์ดหดเล็กน้อยตอนกด (`PressableScale`) · การ์ดค่อย ๆ ขึ้นทีละใบ (`RevealIn`) ·
ตัวเลขเงินนับขึ้นแล้วจบที่ค่าจริงเป๊ะ Screen reader อ่านค่าจริงเท่านั้น (`AnimatedFigure`) ·
กราฟวาดจากซ้ายไปขวา (`RevealFromStart`) · Skeleton มีแสงวิ่ง (`Shimmer`) ·
AI กำลังประมวลผล = วงแหวนกระเพื่อม (`AiPulse`) · บันทึกสำเร็จ = เครื่องหมายถูกเด้ง
(`successSnackBar`) · เปลี่ยนหน้า = เฟด + เลื่อนขึ้น (`RiderPageTransitionsBuilder`) ·
แอนิเมชันวนซ้ำมีเวลาจำกัด (Shimmer ≈ 8 วินาที, AiPulse ≈ 19 วินาที) แล้วหยุดนิ่ง

### 2.5 Spacing, radius, elevation

-   Spacing scale: 4, 8, 12, 16, 20, 24, 32 dp
-   Card radius: 24 dp (Hero/Dialog/Bottom sheet 28 dp)
-   Input radius: 16 dp
-   Button: แคปซูล (Stadium)
-   ปุ่มและพื้นที่แตะสำคัญอย่างน้อย 48 dp; ปุ่มหลักสูง 54 dp
-   ธีมสว่าง: เงาอ่อนสองชั้นบนการ์ด Paper/Obsidian; การ์ดสีใช้สีแยกชั้นแทนเงา
-   ธีมมืด: ไม่ใช้เงา ใช้ระดับสีพื้นผิว + เส้นขอบบางมาก
-   ความกว้างฟอร์มสูงสุด 480 dp

### 2.6 Iconography

ใช้ Material Symbols Rounded หรือ Lucide โดยเลือกชุดเดียวเป็นหลักทั้งแอป: - Home:
house - Pickup: store / package - Profit: wallet / chart - Shift:
calendar-clock - Profile: user-round - RoadContext: map-pinned /
triangle-alert

ห้ามผสมไอคอนหลายสไตล์โดยไม่มีเหตุผล

### Navigation behavior

-   Bottom navigation แสดงหลัง Login
-   ฟอร์มเปิดเต็มจอและมีปุ่มย้อนกลับ
-   คงสถานะ/ข้อมูลของแท็บเมื่อสลับแท็บเท่าที่สถาปัตยกรรมรองรับ
-   ห้ามมีปุ่มที่กดแล้วไม่ทำงาน
-   Feature ที่ยังไม่พร้อมให้ซ่อน ไม่ทำเป็นปุ่ม disabled หลอก ๆ
-   Session หมดอายุจากหน้าใดก็ตามให้กลับ Login พร้อมข้อความ `เซสชันหมดอายุ`

## 4. Screen-by-screen UI specification

> ทุกหน้าที่ดึงข้อมูลจาก API ต้องออกแบบ 4 สถานะ: Loading, Empty, Error และ Data
> ตามความเหมาะสมของหน้าจอ\
> Error ต้องเป็นภาษาไทยและมีปุ่ม `ลองใหม่` เมื่อ retry ได้\
> ข้อมูลตัวอย่างต้องมีป้าย `DEMO`\
> ห้ามเพิ่ม Feature หรือข้อมูลที่ API ไม่มี

### 4.1 Authentication และ Onboarding

#### S-SPLASH

-   พื้นหลัง Forest Green หรือไล่เฉดเขียวอย่างบางเบา
-   โลโก้ RiderOS AI และ tagline
-   ภาพประกอบไรเดอร์ขนาดพอดี ไม่บดบังโลโก้
-   Loading indicator ด้านล่าง
-   Error: หัวข้อ `เชื่อมต่อไม่สำเร็จ`, แสดงสาเหตุ และปุ่ม `ลองใหม่`
-   การกู้ Session ผิดพลาดต้องไม่ลบ Login เดิม

#### S-LOGIN

-   โลโก้และชื่อแอปด้านบน
-   Tagline: `ผู้ช่วยวางแผนงานและกำไรสำหรับไรเดอร์`
-   ช่องอีเมลและรหัสผ่าน พร้อมปุ่มแสดง/ซ่อนรหัสผ่าน
-   ปุ่ม Primary `เข้าสู่ระบบ`
-   ลิงก์ `ลืมรหัสผ่าน?` และ `ยังไม่มีบัญชี? สมัครสมาชิก`
-   แสดง Server Error เป็น Banner เหนือปุ่ม
-   แสดงข้อความสมัครสำเร็จ/ตั้งรหัสผ่านใหม่แล้ว/เซสชันหมดอายุเมื่อมี

#### S-REGISTER

-   ช่องชื่อที่แสดง, อีเมล, รหัสผ่าน, ยืนยันรหัสผ่าน
-   Helper รหัสผ่าน: `อย่างน้อย 8 ตัวอักษร และไม่ใช่รหัสผ่านที่พบบ่อย`
-   Validation แสดงใต้ช่องที่ผิด
-   ปุ่ม `สร้างบัญชี`
-   ลิงก์กลับ Login
-   ห้ามเพิ่ม Social Login หาก API ยังไม่รองรับ

#### S-FORGOT

-   คำอธิบายสั้น ๆ และช่องอีเมล
-   ปุ่ม `ส่งลิงก์รีเซ็ตรหัสผ่าน`
-   แสดง Error ใต้ช่องหรือ Banner ตามประเภทข้อผิดพลาด

#### S-FORGOT-SENT

-   แสดงข้อความ: `ถ้ามีบัญชีนี้ เราได้ส่งลิงก์ไปแล้ว`
-   ปุ่ม `มีลิงก์/รหัสแล้ว`
-   ปุ่มกลับ Login
-   หมายเหตุ DEV ONLY เรื่องลิงก์ใน Server Log แสดงเฉพาะ Build ทดสอบเท่านั้น

#### S-RESET

-   ช่องลิงก์รีเซ็ตทั้งเส้นหรือรหัส
-   ช่องรหัสผ่านใหม่และยืนยันรหัสผ่าน
-   ปุ่ม `ตั้งรหัสผ่านใหม่`
-   สำเร็จแล้วกลับ Login พร้อม Banner

#### S-ONBOARDING

-   หัวข้ออธิบาย: ใช้ข้อมูลนี้คำนวณต้นทุนต่อกิโลเมตร
-   Dropdown ประเภทยานพาหนะ
-   ช่องอัตราสิ้นเปลือง กม./ลิตร
-   ช่องราคาน้ำมัน บาท/ลิตร
-   ช่องค่าเสื่อม บาท/กม.
-   ทุกช่องไม่บังคับตาม API
-   แสดง `เขตเวลา Asia/Bangkok` และ `สกุลเงิน THB`
-   ปุ่ม `บันทึกและเริ่มใช้งาน` และ Secondary `ข้ามไปก่อน`

### 4.2 Home

#### S-HOME

ลำดับเนื้อหา: 1. Header `สวัสดี {ชื่อ}` พร้อมอีเมล และ Logout ตามสถานะปัจจุบัน 2.
การ์ด `วันนี้ · {วันที่}`: กำไรสุทธิเด่นที่สุด 3. รายได้, ค่าใช้จ่าย, ชั่วโมงทำงาน,
กำไรสุทธิ/ชม. 4. การ์ด `สัปดาห์นี้ · {จันทร์–อาทิตย์}` พร้อมตัวเลขชุดเดียวกัน 5. Quick
actions: เพิ่มรายได้, เพิ่มค่าใช้จ่าย, บันทึกช่วงทำงาน 6. ลิงก์
`ดูกำไรทั้งหมด (TrueProfit)`

การออกแบบ: - กำไรสุทธิเป็นตัวเลขขนาดใหญ่ - รายได้/ค่าใช้จ่ายเป็น tile สองคอลัมน์ -
ใช้เขียวสำหรับกำไรบวก แดงสำหรับกำไรติดลบ ศูนย์ใช้สีข้อความปกติ - เมื่อไม่มีชั่วโมงทำงาน
แสดง `—` พร้อมคำอธิบายที่กำหนด - Empty: `ยังไม่มีรายการในวันนี้และสัปดาห์นี้` แต่ Quick
Actions ต้องยังอยู่ - รองรับ Pull-to-refresh

### 4.3 TrueProfit

#### S-PROFIT

-   AppBar `TrueProfit` และทางไปหน้ารายการทั้งหมด
-   Segmented control: วัน / สัปดาห์ / เดือน
-   แถบเลือกช่วงเวลา: ก่อนหน้า, ป้ายช่วง, ช่วงปัจจุบัน, ถัดไป
-   การ์ด `สรุปกำไรจริง`: กำไรสุทธิ, รายได้, ค่าใช้จ่าย, ชั่วโมงทำงาน, กำไร/ชม.,
    รายได้/ชม., จำนวนรายการ
-   กราฟแท่งแนวโน้มกำไรสุทธิ: วัน 30 แท่ง, สัปดาห์ 12 แท่ง, เดือน 12 แท่ง
-   แท่งบวกสีเขียว แท่งลบสีแดง
-   แตะแท่งเพื่อดูวันที่และจำนวนเงิน
-   หมายเหตุชัดเจนว่าตัวเลขมาจากรายการจริงที่ผู้ใช้บันทึก และไม่รวม Shift Simulator

#### S-RECORDS

-   Tabs: รายได้ / ค่าใช้จ่าย / ช่วงทำงาน
-   รายการเรียงใหม่ไปเก่า
-   ใช้ List Tile อ่านง่าย มีวันที่ หมวด จำนวนเงิน และรายละเอียดตามชนิด

## 5. Component library

ทุก Component ต้องรองรับ Light/Dark และสถานะที่เกี่ยวข้อง

### 5.1 Buttons

-   Primary: พื้นเขียว ตัวอักษรสีขาว สูง 52 dp
-   Secondary: พื้น Mint หรือพื้นโปร่ง ขอบเขียว
-   Text: ไม่มีพื้นหลัง ใช้สี Brand
-   Destructive: แดง ใช้เฉพาะการลบ
-   States: default, pressed, loading, disabled (ใช้เฉพาะเมื่อ action
    ใช้ไม่ได้จริง)

### 5.2 Inputs

รองรับ Text, Number, Date, Time, Dropdown และ Multiline - Label
อยู่เหนือช่อง - Helper อยู่ใต้ช่อง - Error แสดงใต้ช่องแบบ Inline - Focus border
ใช้สี Brand - Numeric input ต้องเปิด Numeric keyboard - Password มี
Show/Hide - Dropdown มี Loading/Error/Retry เมื่อโหลดข้อมูลไม่สำเร็จ

### 5.3 Cards และ metric tiles

-   Summary card: ตัวเลขหลัก + label + คำอธิบาย
-   Metric tile: 2 คอลัมน์บนมือถือ
-   แยกเงินจริงและค่าประมาณอย่างชัดเจน
-   ไม่ใช้สีอย่างเดียวสื่อความหมาย ต้องมี label หรือเครื่องหมายประกอบ

### 5.4 Banners

-   Info: ฟ้า/เขียวอ่อน
-   Warning: Amber
-   Error: แดง
-   Success: เขียว
-   มีไอคอนและข้อความสั้น อ่านเข้าใจง่าย

### 5.5 Badges

-   `DEMO`
-   `ค่าประมาณ`
-   `Dataset`
-   `ร้านของฉัน`
-   ระดับข้อมูล: เพียงพอ / จำกัด / ไม่เพียงพอ

### 5.6 Loading / Empty / Error

-   Loading: skeleton ที่คล้ายโครงสร้างข้อมูลจริง
-   Empty: ไอคอนเรียบง่าย, ข้อความอธิบาย, CTA สร้างข้อมูลแรก
-   Error: ข้อความไทย, สาเหตุเมื่อเปิดเผยได้, ปุ่ม `ลองใหม่`
-   ห้ามใช้ Loading spinner ค้างโดยไม่มีข้อความหรือทางออก

### 5.7 Charts

-   Profit bar chart: บวกเขียว ลบแดง
-   Pickup heatmap: แสดงเฉพาะชั่วโมงที่มีข้อมูล
-   Shift comparison: เน้นการเทียบค่าตัวเลขมากกว่ากราฟตกแต่ง
-   มี label/tooltip และรองรับหน้าจอเล็ก
-   หลีกเลี่ยงการใช้สีหลายสีโดยไม่มีความหมาย

### 5.8 Dialog / Snackbar

-   Dialog ยืนยันทุกการลบ
-   Snackbar แสดงผลบันทึกสำเร็จ
-   Server Error แสดง Banner เหนือปุ่มบันทึก
-   ระหว่างส่งข้อมูลปุ่มบันทึกแสดง Spinner และกดซ้ำไม่ได้

## 6. Global UX rules --- ข้อบังคับ

1.  ทุกหน้าที่ดึงข้อมูลต้องมี Loading, Empty, Error, Data
2.  ห้ามมีปุ่มที่กดแล้วไม่ทำงาน; Feature ยังไม่พร้อมให้ซ่อน
3.  เงินทุกจำนวนมาจาก Server, ทศนิยม 2 ตำแหน่ง, คั่นหลักพัน
4.  กำไรบวกสีเขียว, ติดลบสีแดง, ศูนย์สีปกติ
5.  ไม่มีชั่วโมงทำงานให้แสดง `—` พร้อมคำอธิบาย
6.  Shift Simulator ต้องติดป้าย `ค่าประมาณ` และไม่ปนกับ TrueProfit
7.  Pickup ใช้คำว่า `Order-to-Pickup` เสมอ แสดงเป็นช่วง low--high
    และเตือนว่าเป็นข้อมูลต่างประเทศ
8.  หน้าข้อมูลโมเดลต้องมี Meituan acknowledgement ตามข้อความที่กำหนด
9.  ข้อมูล Demo ต้องมีป้าย `DEMO`
10. Form Error แสดงใต้ช่อง; Server Error แสดง Banner เหนือปุ่มบันทึก
11. ระหว่างบันทึกให้ Spinner และป้องกันการกดซ้ำ
12. การลบต้องมี Dialog ยืนยันเสมอ
13. ภาษาไทยทั้งหมด ยกเว้นชื่อเฉพาะ/คำศัพท์เทคนิคที่ระบุ
14. วันที่ไทย เช่น `10 พ.ย. 2026`; เวลา 24 ชั่วโมง เช่น `18:30`; สัปดาห์เริ่มวันจันทร์
15. รองรับจอ 360--430 dp, มือเดียว, กลางแดด และถุงมือ
16. พื้นที่แตะสำคัญอย่างน้อย 48 dp
17. รองรับ Light และ Dark
18. ห้ามเพิ่มข้อมูล/Feature ที่ไม่มีใน API

## 7. Accessibility และ Responsive

-   ออกแบบหลักที่ความกว้าง 360, 390, 430 dp
-   ใช้ SafeArea และรองรับ keyboard inset
-   ฟอร์มเลื่อนได้และปุ่มหลักไม่ถูก keyboard บัง
-   ข้อความไม่ถูกตัดโดยไม่จำเป็น
-   รองรับ font scaling
-   Contrast ต้องอ่านได้กลางแดด
-   ปุ่มสำคัญไม่วางชิดกัน
-   อย่าใช้สีเป็นตัวบอกสถานะเพียงอย่างเดียว
-   ทดสอบภาษาไทยจริง ไม่ใช้ข้อความ placeholder ภาษาอังกฤษ

## 8. Flutter implementation guidance

-   ใช้ Material 3
-   แยก ThemeData สำหรับ Light/Dark
-   สร้าง Design Tokens กลาง เช่น `AppColors`, `AppTypography`,
    `AppSpacing`, `AppRadius`
-   สร้าง reusable components: `PrimaryButton`, `AppTextField`,
    `MetricCard`, `StatusBanner`, `EmptyState`, `ErrorState`,
    `LoadingState`, `SectionHeader`, `BottomNav`
-   แยก Screen ตาม feature/module ไม่เขียนทุกหน้าไว้ในไฟล์เดียว
-   ใช้ข้อมูลจาก API จริงตาม model/schema ที่มี ห้ามสร้าง mock data
    เพื่อแทนข้อมูลจริงโดยไม่ติดป้าย DEMO
-   อย่าเปลี่ยนชื่อ field, validation, business rules หรือ API contract
    เพื่อให้เข้ากับ UI
-   หาก API ยังไม่มีข้อมูลสำหรับ Widget ใด ให้ไม่แสดง Widget นั้น
    แทนการสร้างข้อมูลปลอม
-   ใช้ chart package ที่เหมาะสมและรองรับ tooltip/accessibility
-   ทำ responsive layout สำหรับมือถือก่อน
